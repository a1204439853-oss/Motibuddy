# AI 服务开发指南

该目录提供桌面开发环境使用的本地 AI 服务。运行环境为 Node.js 24，依赖复用项目的 Zod 数据契约。供应商配置只保留在服务端，不进入前端构建或桌面发布资源。

## 配置与启动

1. 将 `server/.env.example` 复制为 `server/.env.local`，在私有文件中填写自己的供应商配置。
2. 从项目根目录执行 `npm run agent:server`。
3. 在另一终端运行 `npm run tauri:dev`，测试桌面交互。

`scripts/configure-agent-secret.mjs` 支持通过不回显的标准输入设置密钥；可选腾讯云播报配置由 `scripts/configure-tts-secret.mjs` 处理。不要在命令行参数、截图、日志或提交记录中粘贴真实凭据。

构建桌面开发产物后，可以使用根目录的 `Start-MotiBuddy-AI.cmd`。启动器检查并复用可用服务，必要时启动服务后再打开桌面程序。源码或环境配置变化后需要重新启动服务。启动器保留原有实例检测，不结束不明进程。

## 服务边界

- 默认只监听回环地址，校验允许的开发与桌面来源。
- 客户端自动建立短期会话，不要求用户输入供应商凭据。
- 校验输入长度、响应结构、并发与调用额度；失败时返回受控错误，不回传供应商错误正文。
- 任务与手账保存由桌面端确认后提交；模型不能自行宣称已完成数据库操作。
- 语音合成由服务端签名，客户端只提交文本与公开音色选项。

该本地服务不是面向公网的多租户部署方案。公开部署应使用独立 HTTPS 服务、真实用户认证、持久化配额和监控；不能将开发凭据随桌面程序分发。

## 验证

```powershell
npm run check
node scripts/check-agent-secrets.mjs
```

真实供应商接口验证与隔离浏览器测试分开执行。前者需要开发者自己的配置，后者使用合成数据和模拟服务，不读取用户账户数据。天气接口验证可运行 `node scripts/verify-weather.mjs`，使用北京公开参考坐标，不读取设备位置。

桌面原生存储、系统通知、系统语音识别与小组件需要 Tauri 环境。`npm run dev` 用于网页界面调试，不能代替原生功能验证。
